### 번호와 내비게이션 규칙

- **번호 하나로 통일**: 큰 번호 = 화면 번호 = 푸터 번호 (`본문 · 04 / 16`). 부록은 큰 글자 A~E와 `부록 B · 본문 07장 보충 · 13 / 16`.
- **목차**: 웹 첫머리에 본문 11 + 부록 5 목차를 두었다. 각 항목은 `#board-NN` 앵커로 이동하고, 체험형(08·10장)에는 '체험' 표시가 붙는다.
- **보드 이름**: 웹의 보드 제목은 `04 · 조사와 핵심 인사이트`, `부록 A (12) · 교환 처리 상태` 형식이다 (내부 'P07-B', 'STEP 2C 추가' 제거).
- **참조 문구**: '설명용' 배지는 '직접 체험은 08장 / 10장', 폰 안 안내는 '체험은 10장'으로 바꿨다. 본문의 장·부록 참조는 모두 실제 보드를 가리킨다 (자동 검사).
- **시각 위계**: 본문 푸터에 이야기 흐름(개요 → 문제 → 조사·인사이트 → 전략 → 솔루션 → 실험 기능 → 검증·회고)을 표시하고 현재 단계를 강조했다 (색 + 글 + `aria-current`). 부록은 큰 글자와 칩을 회색으로 낮춰 본문보다 덜 강조했다. 인사이트(04)·의사결정(07)·솔루션(08)은 숫자 근거와 화면 예시를 붙여 무게를 두었다.

## 2. 04장 리서치·인사이트

원본 분류표 `Seat-Swap-X-Research.xlsx` 의 21개 행을 다시 계산해 모든 수치를 대조했다 (`check_research_4c2a.py`). 행별 '조건 개수'와 조건 태그의 합이 21행 모두 일치하고, 평균은 81 ÷ 21 = 3.857이다. 그래서 이전의 '엑셀 대조 전' 표기를 '원본 분류표(엑셀) 행 단위 대조 완료'로 바꿨다. 게시글 원문을 다시 열어 분류를 재검토하지는 않았다 (X 로그인 제한).

**한계로 함께 표시한 것**

- 연석 요청 0건: 원문을 확보하지 못한 검색 발췌와 다른 플랫폼 글은 표본에서 뺐다. 그래서 수요가 '없다'가 아니라 '이 표본에서 관찰되지 않았다'로 쓰고, 연석은 실험 기능으로 분리했다.
- 표본: 목표 50건 중 21건, 1인 분류, 검색엔진 경유 수집.
- 인터뷰·사용성 테스트는 하지 않았다. AI 시뮬레이션(Nemotron 시나리오 8개)은 '설계 점검용'으로 따로 표시했고 사용자 근거로 쓰지 않았다 (이전에는 '사용자 인터뷰' 카드 안에 섞여 있었다).

## 4. 11장 검증 · 한계 · 회고

이전 문구 "새 상태·예외 화면은 정적 시연이에요. 실제 매칭·알림·티켓 처리와 클릭 전환은 아직 없어요"는 현재 구현과 맞지 않아 전면 교체했다.

- **구현·기술 검증 (완료)**
  - 좌석·회차 교환 체험 (08장), 연석 교환 체험과 신청자·수신자 양쪽 시뮬레이션 (10장)
  - 상태 10개, 예외 6개 화면 (부록 A·B)
  - UX 라이팅: 8,869자 → 7,100자
  - 자동 점검 7개 묶음의 점검 항목 수: 33 · 66 · 184 · 146 · 104 · 61 · 57. 실제 로그와 대조했다 (`check_research_4c2a.py`). 같은 화면을 여러 묶음이 함께 점검하므로 합산하지 않는다고 적었고, 사용성 검증이 아니라고 명시했다.
- **아직 검증하지 않은 것**: 사용자 인터뷰, 사용성 테스트, 이해도·교환 성공률, 실제 교환·연석 수요, NOL티켓 운영 정책·기술 연동. "효과를 주장하지 않는다"고 명시했다.
- **회고**: 발견한 문제 → 설계한 것 → 선택의 근거와 제약 → 다음에 할 일. 하지 않은 검증이나 성과는 쓰지 않았다.
