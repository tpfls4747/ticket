# STEP 4B.5 — UX 라이팅·정보 밀도 다듬기

모바일 화면의 문구를 줄여, 사용자가 **판단과 행동에 필요한 정보만** 보도록 다듬었다.
레이아웃·디자인 시스템·기능·매칭 판정 로직은 바꾸지 않았다 (엔진은 문구만 수정). 보드는 16장 그대로다.

- 적용 스크립트: `tools/authoring/apply_writing_4b5.py` (STEP 4B 커밋 상태의 `src/` 에서 1회 실행)
- 엔진 문구: `tools/authoring/demo3b_store.js`, `tools/authoring/demo3c_pair.js`
- 텍스트 감사 도구: `tools/text_audit.cjs` (모든 폰 화면을 펼쳐 기본으로 보이는 글자를 화면별로 센다. 스크린 리더 전용 글자와 닫힌 `details` 안의 글자는 제외)
- 증빙: `verify/results-4b5/`

## 1. 원칙

| 원칙 | 적용 |
|---|---|
| 한 화면 한 메시지 | 제목 = 현재 상태 또는 다음 행동. 부제는 1~2문장 |
| 이미 보이는 정보는 반복하지 않기 | 단계 표시가 '실패/중단'을 보여 주면 단계 아래 같은 뜻의 문장은 뺐다. 지난 단계의 보조 설명도 뺐다 (단계 이름과 완료 표시로 충분) |
| 배지·단계·본문이 겹치지 않기 | 양방향 확인의 배지는 '미확인 n건' 또는 '매칭 완료 아님' 하나만 |
| 설계 설명과 사용자 안내를 나누기 | '서비스 설계 가정', '목표 UX·시스템 요구사항', '…라고 가정한 모의 화면이에요' 같은 긴 문장은 앱에서 빼고, 확대 보기 패널의 **설계 메모**로 옮겼다 |
| 시뮬레이션 표기는 짧게 | 화면마다 '시연' 태그 하나. 값 옆에는 '(가상)', '(목표)', '(가상 규칙)' 만 붙인다 |

## 2. 화면별 감사표

중요도: **상** = 판단에 꼭 필요한 정보(유지·짧게) · **중** = 행동 안내(짧게) · **하** = 보조 설명 또는 설계 설명(필요한 곳에만 / 포트폴리오로 이동)

| 화면 | 현재 문구 (4B) | 개선 문구 (4B.5) | 수정 이유 | 중요도 | 유지해야 할 정보 |
