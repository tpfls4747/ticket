# STEP 4B: UX/UI 시각 다듬기

새 기능을 늘리지 않고, 지금 구현된 Seat Swap 프로토타입이 핵심 경험을 더 분명하게 전달하도록 다듬었다. 주요 컬러, 타이포그래피, 콘텐츠, 16개 보드 구성, 핵심 인터랙션은 그대로다. 매칭 엔진의 판정 규칙(인접·조건·흐름)도 바꾸지 않았다. 화면 데이터와 표시 방식만 바꿨다.

## 1. 수정한 UX/UI 문제

| 문제 (STEP 4A까지) | 해결 |
|---|---|

| 일반 교환과 연석 교환의 단계 표시가 달랐다 | **공용 단계 표시 컴포넌트**: 현재·완료·남은·실패·중단 상태를 구분한다. 현재 단계 이름과 다음 단계는 텍스트로, 현재 단계에는 `aria-current="step"`을 붙이고 단계마다 스크린 리더 문구를 둔다 |
| P13에서 체크박스를 눌러도 버튼이 켜지지 않았다 | **설명용 화면 방식 채택**: P13 폰의 입력 요소(확인 체크박스, 교환 제안 받기 라디오)를 그림으로 바꾸고 '설명용 화면 · 체험은 07 보드' 표시를 붙였다. 보내기 버튼은 비활성 상태와 이유를 그대로 보여준다. 실제 체험은 P12 체험 폰에서 한다 |

## 2. 화면 확대 보기 구현 방법

런타임 구조를 바꾸지 않는 가장 단순한 방법을 골랐다.

- 각 폰은 원래 `transform: scale(0.58)`로 그려진 하나의 DOM이다. 확대할 때 이 요소의 스타일만 `position: fixed; transform: none` 실제 크기로 바꾸고, 닫으면 원래대로 돌린다. 화면을 복제하지 않으므로 체험 상태, 입력값, 스크롤이 그대로이고, 확대한 상태에서도 바로 조작할 수 있다. 배율 변환이 없어 글자가 흐리지 않다.
- 페이지 로직에 `zoom` 상태 하나를 추가했다. 단일 폰은 `[i]`, A·B 함께 보기는 `[0, 2]`다.
  - 확대 패널: 역할, 화면 이름, 도움말, 이전·다음 화면(보드 순서), 닫기
  - 배경 막
  - 화면 밖 알림 영역(aria-live): '크게 보기 열림: … Esc 로 닫아요'
- Esc는 확대가 열려 있으면 확대만 닫는다. 체험 초기화로 이어지지 않고, 닫혀 있을 때는 기존처럼 처음 상태로 돌린다.
- 정적 보드(P09·P11·P13)에도 같은 로직을 넣었다. P10의 화면 이동 링크는 확대 상태에서도 동작한다.

## 3. 디자인 시스템 변경

- **크게 보기 버튼**: 폰 오른쪽 위 30px 원형 버튼(어두운 배경, 흰 테두리, 돋보기 아이콘, `aria-label="… 크게 보기"`)
- **시연 제어판**: 600px, 2px 점선 #191B22, 배경 #F5F6F8, 모서리 18px, 보드 오른쪽 위(right 120px, top 30px). DEMO 표시, 다음 단계(aria-live), 시나리오 행, 조작 행. 버튼은 검정(진행), 빨강 테두리(실패), 흰 테두리(보조)
- **설명용 표시**: 같은 위치의 알약형 배지(1.5px 점선 #8B909C)
- **단계 표시**: 6px 막대 × 단계 수. 완료와 현재는 #5B3DF5(현재는 이중 테두리), 남은 단계 #E6E8EC, 실패 #B03A3A, 중단 #8B909C. 머리글 '단계 n/N · 이름'과 '다음: …', 끝 상태 문구가 붙는다. 일반 교환 6단계(조건 등록 · 후보 확인 · 비교·제안 · 상대 수락 · 최종 확인 · 교환 완료), 연석 6단계(교환 방식 · 유지할 좌석 · 인접 확인 · 비교·제안 · 상대 수락 · 최종 확인), 수신자 5단계
- **교환 요약 카드(hero)**: 공연·회차 한 줄, '지금 → 바뀔 좌석'(17px 굵게), 결과 한 줄
- **접힘 영역**: `<details>`(키보드로 열고 닫기 가능)로 같은 항목, 조건 전체, 배치도 제외 좌석을 넣는다
- **수신자 상태 색 띠**: 도착·검토(보라), 수락(초록), 최종 확인(주황), 완료(초록 굵은 테두리), 실패(빨강 굵은 테두리), 거절·취소(회색). 항상 배지 텍스트와 함께 쓴다
- **비활성 버튼**: STEP 4A 규칙(잠금 아이콘 + 점선) 유지

## 6. 의도적으로 바꾸지 않은 것

- 신청 현황(Waiting) 화면에는 원래 세로 진행 목록이 있어 단계 표시를 겹쳐 넣지 않았다.
- 진행 현황(StatusSent, StatusAccepted, PairAccepted)의 세로 타임라인은 그대로 두었다. STEP 4A에서 이미 같은 데이터 형식(`timeline`)으로 통일돼 있다.
- 표지(P01)의 폰은 장식용이라 크게 보기를 넣지 않았다.
- 응답 기한 카운트다운, 동시 제안, 상태 저장, 실제 좌석 데이터, NOL API, 실제 예매·양도는 추가하지 않았다. 기한과 정책은 '가상 규칙'·'시연 판정' 표기를 유지했다.

**4B 시각 검증이 확인하는 것**
- 보드 16개
- 크게 보기
  - 크기·선명도: 확대 전 최소 글자 6.4px, 확대 후 390×844 실제 크기에 최소 글자 11px 이상, 배율 변환 없음
  - 상태 유지: 확대한 상태에서 조작할 수 있고, 닫아도 상태가 그대로이며 Esc 로 초기화되지 않음
  - 닫기·이동: Esc·닫기 버튼·배경 클릭으로 닫힘, 닫으면 포커스가 버튼으로 돌아감, Tab 은 확대 영역 안에서만 돎, 이전·다음 화면이 보드 순서를 따름

- 수신자 상태 7종과 신청자 취소: 화면의 배지·제목이 엔진 결과와 같음

- 공용 단계 표시: 머리글, `aria-current`, 단계별 스크린 리더 문구, 실패 표시
- 정보 위계: 표시 순서, 접힘 기본값, 펼치기
- P13 설명용 화면: 입력 요소 0개
- 정적 보드 크게 보기
- 콘솔 오류·경고·리소스 로드 실패 0건

**기존 테스트에서 의도적으로 바꾼 부분**
- 화면 텍스트를 읽는 도우미가 접힌 영역(`details`)을 잠시 펼쳐 읽고 되돌린다. 기존 문구 검사를 그대로 유지하기 위해서다.
- 제안이 도착하면 수신자가 '제안 검토하기'를 눌러 연다. 이전에는 자동으로 화면이 바뀌었다.
- 단계 문구가 '단계 n/4'에서 '단계 n/6'으로 바뀌었다.
- 제어판 이름이 '시연용 제어'로, 안내 문구가 '수신자 B 폰'으로 바뀌었다.
- `test_nav.cjs`
