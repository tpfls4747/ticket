# STEP 4A: UX 결함 해결 및 사용자 흐름 완성

새 기능을 늘리는 단계가 아니다. STEP 3B(일반 교환)와 STEP 3C(연석 교환) 체험에서 드러난 UX 문제를 고쳐서, 신청자와 수신자가 같은 상태를 보면서 이해하고 조작할 수 있게 만든다.

- 모든 좌석·정책·상대 계정은 **시연용 모의 데이터**다. 실제 예매처, 결제, 계정과는 연결되지 않는다.
- 연석 교환은 계속 **실험 기능 · 수요 미검증**이다.
- 인터뷰와 사용성 테스트는 진행하지 않았다.
- 디자인 시스템과 16개 보드 구성은 그대로다. 대규모 리디자인은 STEP 4B에서 한다.

## 1. 해결한 UX 문제

| STEP 3C까지의 문제 | STEP 4A의 해결 |
|---|---|
| 수신자 화면(PairReceive, PairIntent)이 정적이었다. 수락·거절은 신청자 폰 안의 데모 버튼으로만 할 수 있었다 | P12 **3번 폰을 수신자(11열 5번 관객) 체험 폰**으로 바꿨다. '교환 제안 받기' 설정(PairIntent)과 제안 검토·수락·거절(PairReceive)이 동작한다. 신청자 폰(1번)과 **같은 상태**를 참조한다 |
| '후보 아님' 카드에서 특정 좌석 관객의 수신 동의 여부를 추론할 수 있었다. 조건 불일치·자격 미확인·동행 같은 개인 사유도 그대로 보였다 | 신청자에게는 **연결 가능한 후보만** 보여준다. 후보가 없으면 "현재 연결 가능한 후보가 없습니다"라고 중립적으로 안내한다. 좌석 배치(통로, 배치도 정보 없음)는 사람 정보가 아니므로 좌석 단위로 계속 알린다 |
| 수신 의향·수락·동의 용어가 섞여 있었다. 지금 모델과 맞지 않는 문구도 있었다('다른 후보에게 보낸 제안은 닫혔어요') | 아래 용어 기준으로 통일했다. 공용 화면은 일반 교환과 연석 교환에서 각각 맞는 문구를 보여준다 |
| 지킬 좌석과 내놓을 좌석이 두 번째 화면에서야 나왔다. 연석 흐름에는 단계 표시가 없었다 | 첫 화면부터 '유지할 좌석 / 교환에 제공할 좌석'을 안내한다. 단계 1/4~4/4를 표시한다 |
| 후보가 없을 때 안내 문구만 있었다. 거절 뒤 반대 방향 버튼은 방향만 바꿨다 | 후보가 없으면 같은 화면에서 '반대 방향으로 찾아보기'를 제공한다. 거절 뒤에는 '다른 후보 찾기'와 '이전 단계로'를 제공한다 |
| 보내기 전 화면에 좌석·조건 비교가 흩어져 있었다 | '보내기 전 최종 비교' 표 하나에 모았다(유지할 좌석, 제공할 좌석, 좌석 배치, 회차, 등급·가격, 상대 좌석) |
| 데모 패널(상대방 수락·거절, 최종 확인 결과, 11열 5번 상황)이 휴대폰 화면 안에 있었다 | 폰 밖 **시연 제어판**으로 옮겼다(P08은 보드 오른쪽 위, P12는 오른쪽 카드 아래). DEMO 표시와 '실제 서비스 기능이 아니에요'를 붙였다 |
| 화면 전환을 스크린 리더에 알리지 않았다. 비활성 버튼은 색으로만 구분됐다 | 체험 폰마다 짧은 aria-live 알림(화면 제목과 상태), 상태 메시지 `role="status"`를 추가했다. 비활성 버튼에는 잠금 아이콘과 점선 테두리를 붙였다 |

## 2. 용어 기준

| 용어 | 뜻 | 쓰는 곳 |
|---|---|---|
| **교환 제안 받기** | 수신자의 사전 수신 의향. 기본값은 꺼짐이며 언제든 끌 수 있다(진행 중인 제안이 있으면 응답한 뒤에) | PairIntent, 후보 화면 안내, P07 상태 흐름 보드 |
| **교환 제안 보내기** | 신청자의 제안 | 일반 교환 비교 화면, 연석 최종 비교 화면, 진행 현황 타임라인 |
| **제안 수락** | 수신자의 개별 동의. 수락해도 아직 교환 완료가 아니다 | PairReceive, 진행 현황, PairAccepted, StatusAccepted |
| **최종 확인 중** | 예매처가 처리 가능 여부를 검토하는 단계 | StatusFinal, 수신자 상태 |
| **교환 완료** | 시연의 최종 성공 상태 | 완료 화면, 수신자 상태 '교환 완료 (시연)' |

고친 문구는 다음과 같다.
- 연석 완료 화면: '의향을 등록한 다른 후보에게 보낸 제안은 닫혔어요' → '교환에 제공한 B구역 7열 12번 좌석은 옆자리 관객의 새 좌석이 됐어요'
- P12 4번 폰 캡션: '다른 후보에게 보낸 제안은 자동으로 닫혀요' → '최종 확인을 통과해야 교환 완료로 표시해요'
- 진행 현황:
  - '제안 전송 · 내 수락(동의) 완료' → '교환 제안 보내기 · 비교 화면에서 내 동의 완료'
  - '상대방 수락' → '제안 수락'
- 수락 화면: '상대방이 수락했어요' → '상대방이 제안을 수락했어요'
- 연석 화면들: '제안 수신에 동의한 관객' / '교환 의향 등록' → "'교환 제안 받기'를 켠 관객"
  - 바뀐 곳: PairMode, PairSeat, PairReceive, KEY DECISION, P07 상태 흐름 보드
- 좌석 이름: '지킬 좌석 / 내놓을 좌석' → '유지할 좌석 / 교환에 제공할 좌석'

공용 화면의 문구 분기:

| 화면 | 일반 교환 (P08) | 연석 교환 (P12) |
|---|---|---|
| StatusSent 타임라인 | 교환 신청 → 후보 확인 → 교환 제안 보내기 → 상대방 검토 → 제안 수락 → 최종 확인 중 → 교환 완료 | 좌석 방향 선택 → 옆자리 후보 확인 → 교환 제안 보내기 → … |
| StatusSent 안내 | 내 티켓은 그대로 유효해요 | 내 티켓 2장은 그대로 유효해요 |
| ExCancelled | 교환 신청을 취소했어요 · [교환 다시 신청] [예매 상세로] | 교환 제안을 취소했어요 · [좌석 방향 다시 고르기] [처음으로] |
| ExFinalFailed | 내 티켓 1장 · 유지 (목표) | 내 티켓 2장 · 2장 모두 유지 (목표) |

## 3. 수신자 사용자 여정 (P12 3번 폰 · 11열 5번 관객)

1. **교환 제안 받기 설정** (PairIntent): 시작 상태는 '지금: 교환 제안 받지 않음 (기본값)'이다. 받기를 고르고 **설정 저장**을 눌러야 적용된다(저장 전에는 '설정 저장을 눌러야 적용돼요' 안내). 화면에서 "'교환 제안 받기'와 '제안 수락'은 달라요"를 설명한다.
2. 신청자가 교환 제안을 보내면 수신자 폰이 **제안 검토**(PairReceive)로 바뀐다(알림 도착을 가정).
   - 지금 내 좌석과 바뀔 좌석을 보여준다.
   - 비교 항목: 회차 같음, 등급·가격 같음(추가 결제 없음), 11열 5번 → 7열 12번, 무대와 거리 4열 앞으로.
   - 동행 좌석이 있으면 분리 안내를 보여준다.
   - '수락해도 최종 확인을 통과해야 교환 완료예요'를 안내한다.
3. **제안 수락** 또는 **거절**을 고른다.
   - 수락하면 '제안을 수락했어요 · 아직 교환 완료가 아니에요'가 뜬다. 이후 상태는 최종 확인 중 → 교환 완료 (시연)/최종 확인 실패 순서로 같은 화면에 갱신된다.
   - 거절하면 '내 좌석은 그대로예요. 거절 사유는 신청자에게 공개되지 않아요'가 뜬다.
   - 신청자가 취소하면 '신청자가 제안을 취소했어요'가 뜬다.
4. 뒤로를 누르면 설정 화면으로 간다. 진행 중인 제안이 있으면 '도착한 교환 제안 1건 보기' 버튼이 나오고, 받기를 끌 수 없다는 잠금 안내가 붙는다. 이때 끄려고 하면 거부 안내가 뜬다.

신청자 폰과 수신자 폰은 페이지 로직의 같은 상태(`demo3c_pair.js`)를 본다.
- 수신자가 받기를 켜면 신청자 후보 화면에 바로 후보가 나타난다.
- 수신자가 끄면 신청자의 선택이 풀린다. 신청자가 최종 비교 화면에 있었다면 후보 화면으로 돌아가 중립 안내를 받는다.

## 4. 개인정보 보호 방식

- 신청자 후보 화면에는 다음 두 가지만 보여준다.
  - '교환 제안 받기'를 켠 관객 가운데 인접·자격·조건이 모두 맞는 좌석 (연결 가능 카드)
  - 신청자가 직접 보낸 제안의 결과 (거절된 제안)
- 다음 정보는 신청자 화면 어디에도 표시하지 않는다.
  - 다른 관객이 수신 동의를 했는지
  - 상대가 등록한 조건과 불일치 사유
  - 상대 티켓의 자격 확인 상태
  - 동행 좌석 여부
- 후보가 없으면 "현재 연결 가능한 후보가 없습니다. 좌석별로 빠진 이유는 개인정보라 알려드리지 않아요"라고 안내한다.
- 좌석 배치는 사람이 아니라 공연장의 정보이므로 보여준다.
  - '배치도에서 제외한 좌석'에는 통로로 떨어진 좌석과 배치도 정보가 없는 좌석('인접 여부 확인 필요')만 나온다.
  - 배치도상 옆자리인데 후보가 없는 좌석(예: 11열 3번)은 아예 언급하지 않아, 그 관객의 사정을 추론할 수 없게 했다.
- 동행 좌석 분리는 해당 수신자 본인의 화면에서만 구체적으로 안내한다. 신청자에게는 '상대는 일행과 함께 예매했거나 다른 이유로 거절할 수 있어요'라는 일반 안내만 준다.
- 시연 제어판의 '11열 5번 티켓 상황'은 평가자가 시나리오를 바꾸기 위한 시뮬레이션 조작이다. 실제 서비스에서 신청자가 볼 수 있는 정보가 아니라는 점을 제어판에 명시했다.

## 5. 연석 흐름 개선

- **단계 표시**: 1/4 교환 방식 · 2/4 유지할 좌석 · 3/4 옆자리 후보 · 4/4 최종 비교 (막대 4칸과 텍스트, `role="group"` 라벨).
- **첫 화면 안내**: '2장 중 한 장은 유지할 좌석으로 두고, 다른 한 장을 교환에 제공할 좌석으로 옆자리 관객 좌석과 바꿔요'.
- **후보 없음**: 같은 화면에 '반대 방향으로 찾아보기 (7열 12번 유지)' 버튼이 있고, 누르면 방향만 바꿔 후보 화면에 머문다.
- **거절 뒤**: '다른 후보 찾기'(거절한 후보는 '거절된 제안'으로 다시 보낼 수 없음)와 '이전 단계로 (유지할 좌석 다시 고르기)'를 제공한다.
- **최종 비교**: '지금 → 교환 후' 한 줄 비교와 결과 태그(그대로·바뀜·나란히 · 완료 시에만·같음·상대 이동), 양방향 확인, 확인 체크를 거쳐야 보낼 수 있다.
- **뒤로 가기**: 티켓 선택, 교환 방식, 유지할 좌석, 후보 선택, 확인 체크가 모두 유지된다. 제안을 보낸 뒤에는 뒤로가 동작하지 않고 취소로만 나갈 수 있다.

## 6. 시연 제어판 (폰 밖)

| 보드 | 위치 | 조작 |
|---|---|---|
| P08 일반 교환 | 보드 제목 오른쪽 | 상대방 제안 수락 / 상대방 거절 → 최종 확인 시작 → 최종 확인 성공 / 실패 (단계에 맞는 버튼만), 처음부터 다시 |
| P12 연석 교환 | 오른쪽 KEY DECISION 카드 아래 | 단계별 안내(① 3번 폰에서 교환 제안 받기 켜기 → ② 1번 폰에서 제안 → ③ 3번 폰에서 응답 → ④ 최종 확인), 11열 5번 티켓 상황(기본·동행 좌석 있음·조건 불일치·자격 미확인, 제안 전까지만 변경 가능), 최종 확인 시작·성공·실패, 처음부터 다시 |

- 휴대폰 화면 안의 데모 패널은 모두 없앴다. 대상 화면은 StatusSent, StatusAccepted, StatusFinal, PairAccepted, PairAdjacency다.
- 상대방 수락·거절은 일반 교환에서는 제어판에서, 연석 교환에서는 수신자 폰에서 한다.
- 제어판은 점선 테두리, DEMO 표시, 회색 배경으로 서비스 UI와 구분했다.

## 7. 접근성

- **화면 전환 알림**:
  - 체험 폰마다 화면 밖에 숨긴 `aria-live="polite"` 영역을 두고 '화면 제목 + 상태' 한 문장만 넣었다.
    - 예: '보내기 전 최종 비교 화면. 연석 만들기 준비 중'
    - 예: '좌석 교환 제안 화면. 제안 수락함 · 최종 확인 전'
  - 화면 전체를 다시 읽지 않고, 문장이 바뀔 때만 읽힌다.
  - 제어판 안내 문장도 polite 영역이다.
- **상태 메시지**: 진행 불가 이유, 저장 결과, 철회 안내, 후보 없음 안내를 `role="status"` 텍스트로 표시한다.
- **포커스**:
  - 체험 폰에서 화면이 바뀌면 그 폰 틀로 포커스를 옮긴다.
  - 제어판을 조작한 뒤에는 누른 버튼이 남아 있으면 그대로 두고, 버튼이 사라지면 제어판으로 옮긴다.
  - Esc는 폰과 제어판 어디서든 체험을 처음 상태로 되돌린다.
- **비활성 버튼**: 회색 배경 외에 잠금 아이콘과 점선 테두리를 붙였고, 버튼 위에 이유를 텍스트로 보여준다.
  - 적용 화면: Request, Compare, ExMismatch, StatusFinal, ConditionsCast, PairAdjacency, PairWarn
- 선택 상태는 `aria-pressed`와 '선택됨 ✓' 텍스트, 제어판 칩은 `aria-pressed`와 검은 배경으로 함께 표시한다.
