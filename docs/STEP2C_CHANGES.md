# STEP 2C 변경 내역 (UX 구조·화면 상태)

**완료**와 **화면만 구성**을 구분해서 적는다.
- **화면만 구성**: 정적 시연 화면이다. 클릭 전환, 입력 검증, 매칭·알림·티켓 처리 기능은 없다.
- 모든 화면의 데이터는 **시연용 모의 데이터**(가상 공연·가상 가격·가상 판정)이다. 실제 NOL 데이터·API·정책 검증 결과가 아니며, 티켓 소유권을 이전할 수 있다고 가정하지 않았다.

## 3. 기존 화면과 변경 화면의 비교

| 항목 | 이전 (2B) | 이후 (2C) |
|---|---|---|
| 조건 등록 | 회차·구역·열 선택만 | + 필수/선호/무관 선택기, 캐스팅 행, "미선택을 무관으로 처리하지 않음" |

| 완료 표시 | 수락 → 완료 | 상대방 수락 → 최종 확인 중 → 완료(모의)로 분리 |

| 연석 | 방향 선택, 수신자 화면 | + 의향 설정, 인접·자격 확인, 분리 가능성 안내, 거절, 수락 단계 |
| 표지 | 연석 화면 중심 | 일반 교환이 핵심, 연석은 실험 기능 칩 |

## 4. 일반 교환 플로우 구조

교환 자격 확인(가능/확인 필요/불가) → 조건 설정(필수·선호·무관, 미선택 기본값) → **교환 신청** → 양방향 확인(내 조건↔후보 티켓, 후보 조건↔내 티켓) → **후보 발견**(매칭 완료 아님) → 전후 비교 + 내 수락 → **제안 전송** → **상대방 검토** → **상대방 수락** → **최종 확인 중** → **교환 완료**(확인 통과 후에만).
거절·취소·실패는 종료 상태이고 내 티켓은 그대로다 (실패 시 원 티켓 유지는 **목표 UX·시스템 요구사항**이며 이 프로토타입이 처리하지 않는다).

## 5. 연석 교환 플로우 구조 (실험 기능 · 수요 미검증)

수신자 사전 의향(기본값 받지 않기) → 후보 인접·자격 확인(의향 없음=제안 불가, 인접 미확인=보류) → 동행석 분리 가능성 안내 + 전후 좌석 비교 + 내 동의 → 이후는 일반 교환과 같은 상태(제안 전송 → 상대방 검토 → 상대방 수락 → 최종 확인 중 → 완료). 수신자는 언제든 거절할 수 있다. 번호가 이어진다는 이유만으로 인접하다고 판단하지 않는다. 의향이 없는 관객에게는 제안을 보내지 않는다.

## 6. 예외 상태 (7종)

필수 조건 불일치(후보 제외) · 후보 없음 · 상대방 거절 · 신청자 취소 · 티켓 상태 변경(일시 중지·확인 필요) · 최종 확인 실패 · (기존) 응답 시간 초과.

## 9. 아직 동작하지 않는 인터랙션

- 모든 링크(뒤로가기·CTA·화면 이동): 클릭하면 프레임이 `about:blank#blocked` 로 이동해 비어 버림 (기존 문제, `KNOWN_ISSUES.md` A-1)
- 신규 화면의 모든 버튼: 동작 없음 (자격 확인의 "조건 등록하기", 조건 설정의 칩·중요도 선택, 비교의 "교환 제안 보내기", 예외 화면의 모든 CTA, 연석의 설정 저장·제안 보내기 등)
- 중요도 선택기, 조건 칩, 열 슬라이더: 정적 표시 (선택해도 바뀌지 않음)
- 상태 간 전환, 카운트다운, 알림, 매칭, 필수 조건 판정 로직: 없음
- 유일하게 동작하는 입력: 네이티브 체크박스·라디오 (P08 기존, 신규의 동의 체크박스·의향 라디오). 다른 화면 상태와 연결되지는 않음

## 10. STEP 3 신규 인터랙션 구현 계획 (제안)

1. **링크 수정**: 클릭을 가로채 같은 위치에서 화면을 교체 (기존 문제 A-1 해결). 모든 이후 항목의 전제
2. **조건 설정**: 칩 토글, 중요도 선택, 미선택 시 CTA 비활성·경고, 열 범위 입력
3. **자격 확인**: 세 상태 전환 시연과 상태별 다음 행동
4. **양방향 매칭**: 가상 후보 데이터로 필수 불일치 제외·선호 차이 설명을 실제로 계산하는 시연 로직
5. **처리 상태 머신**: 제안 → 검토 → 수락 → 최종 확인 → 완료/실패를 한 화면에서 단계 전환 (수락과 완료 분리 유지)
6. **예외 분기**: 거절·취소·티켓 변경·후보 없음·최종 실패 진입 시연
7. **연석**: 의향 설정 → 후보 필터(의향·인접·자격) → 제안 → 수신자 수락/거절
8. **상태 컴포넌트 데모**, 키보드 포커스·접근성
각 단계는 승인 후 진행하고, 단계마다 `tools/verify_render.cjs` 로 회귀를 확인한다.
