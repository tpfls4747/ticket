STRATEGY ① · 문제와 설계 원칙

발견한 문제를 설계 원칙으로 바꿨어요

인사이트에서 나온 UX 문제마다 지켜야 할 원칙을 정했어요. 규칙 값은 공식 정책이 아니라 프로토타입을 위해 정한 것이에요.

발견한 문제 → 설계 원칙

UX 문제인사이트 1·2조건이 여러 개라 맞는 상대를 찾기 어렵다
설계 원칙 1조건을 구조화하고, 예매처가 양쪽 조건을 대조해 후보를 찾는다
UX 문제인사이트 3꼭 필요한 조건과 양보할 조건이 섞여 있다
설계 원칙 2조건마다 중요도(필수·선호·무관)를 사용자가 직접 정한다. 고르지 않은 조건을 무관으로 처리하지 않는다
UX 문제인사이트 4연락과 처리가 개인 채널에서 이뤄져 과정이 보이지 않는다
설계 원칙 3예매처 안에서 처리하고, 단계와 내 티켓 상태를 항상 보여 준다. 관객끼리 돈·연락을 주고받지 않는다
UX 문제연석 요청 0건연석 수요를 뒷받침할 근거가 없다
설계 원칙 4핵심 기능과 분리한 실험 기능으로 두고, 제안 받기를 켠 관객에게만 제안한다
핵심 원칙 · 가정

교환은 예매처가 처리하고, 관객끼리는 돈도 연락도 주고받지 않아요.

가상같은 가격·등급끼리만 교환차액 정산 없이 처리 단순화 (MVP)
목표두 티켓을 한 번에 교체도중에 좌석을 놓치지 않는 시스템 기능 필요
가상제안 응답 기한 12시간한 사람 때문에 다른 매칭이 막히지 않게
가상교환은 공연당 1회반복 교환으로 좌석을 독점하지 않게
가상공연 전 신청 마감마감 일수는 정하지 않았어요
